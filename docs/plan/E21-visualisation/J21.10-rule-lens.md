# J21.10 Rule lens

Epic: [E21 Panel redesign, dashboard and data exploration](README.md) · Status: todo · Depends on: J21.8
Read: [frontend#rule-builder](../../architecture/frontend.md#rule-builder), [resolution#rule-specification](../../architecture/resolution.md#rule-specification), [resolution#strategies](../../architecture/resolution.md#strategies)

**Objective:** Change how a metric is resolved while looking at its data, and see the effect before saving.

## Outputs
- **Panel:** a side panel on every metric detail page (a bottom sheet on mobile). It contains:
  - the active rule as a plain sentence;
  - source groups to drag into a new order (with a keyboard alternative), plus exclusion chips;
  - strategy, window and minimum-coverage controls, offering only what the metric allows (`GET /metrics/{code}`);
  - warning acknowledgement, such as the duplicate risk of `sum`.
- **Preview:** every change rebuilds the draft spec with `web/src/lib/rules/rule.ts` and calls `POST /resolution/preview` for the visible range. The chart overlays the draft as a ghost series, highlights the windows that change, and shows a summary (windows changed, mean shift, new gaps) with a table of changed windows.
- **Saving:** save, save and activate, and revert all use the existing `/rules/{metric}/versions` and `/activate` endpoints. History shows as a timeline. "Open full builder" covers settings the lens does not edit.
- **Preview API:** `PreviewResolution` is extended to non-day windows only if a metric needs it, along the `GetResolvedSeries` path, and it stays capped like today.

## Done when
- E2E on fake data:
  - reorder, preview, save and activate, then revert;
  - an unacknowledged `sum` cannot be saved;
  - a server field error points back to its control.
- Every change is visible in rule version history.
