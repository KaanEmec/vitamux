# J21.6 Summary, trend and all-sources range API

Epic: [E21 Panel redesign, dashboard and data exploration](README.md) · Status: todo · Depends on: None
Read: [resolution#cache-and-materialization](../../architecture/resolution.md#cache-and-materialization), [resolution#result-shape](../../architecture/resolution.md#result-shape), [api#example-resolved-day](../../architecture/api.md#example-resolved-day)

**Objective:** Serve dashboard cards and long ranges in one call each, without the client stitching hundreds of days together.

## Outputs
- **`GET /api/v1/resolved/summary?metrics=…&date=`.** Per metric, it returns:
  - the window's `ResolvedValue`;
  - a 30-day sparkline;
  - 7-, 30- and 90-day stats over resolved daily values: mean, min, max, n and coverage.
- **`GET /api/v1/resolved/trend?metric&start_date&end_date&grain=week|month`.** Rollups of resolved daily values: mean, min, max, n, coverage, and sum for additive metrics. This lets charts go past the 366-day cap.
- **`GET /api/v1/sources/series?metric&start&end&grain=hour|day`.** A per-source series for the all-sources overlay over long ranges, built on `source_hourly_aggregates`. It states when the aggregates are behind their dirty marks.
- **Common rules:**
  - every endpoint goes through `resolve.Run` and `resolved_cache`;
  - rollups never write back over source data;
  - every response carries the rule refs it used.
- [api](../../architecture/api.md) and [resolution](../../architecture/resolution.md) say that these are display rollups of resolved values, not a new resolution strategy.

## Done when
- A cold dashboard summary (10 metrics) answers in under 500 ms, and a warm one in under 150 ms, on the synthetic 3-year dataset.
- Rollups match a hand computation on fixtures, including DST and timezone-period changes.
