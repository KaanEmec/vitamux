# J21.2 Chart library ADR (amends ADR-0010)

Epic: [E21 Panel redesign, dashboard and data exploration](README.md) · Status: done (2026-10-04) · Depends on: J21.1
Read: [ADR-0010](../../adr/0010-sveltekit-static-spa.md), [frontend#technology](../../architecture/frontend.md#technology)

**Objective:** Choose a richer chart library from measurements, not taste, and record the decision.

## Outputs
- A spike that renders the same three charts with each candidate:
  - a 90-night line with band, status markers and a tooltip;
  - a 14,400-point heart-rate day;
  - a stacked sleep chart with brush-to-zoom.
- Candidates:
  - **LayerChart** (leading): Svelte 5 native, built on D3, tree-shakeable, with SVG and canvas layers and built-in tooltip, brush and zoom.
  - **ECharts**, modular build: the fallback.
  - The current uPlot plus hand-written SVG, as the baseline.
- Each candidate is measured for:
  - the gzip size of the lazy chunk;
  - whether it works under the `style-src 'self'` CSP;
  - render time at 50k points (the `vx-chart-render` mark);
  - keyboard and screen-reader hooks;
  - theming through CSS custom properties;
  - licence (MIT or Apache-2.0);
  - maintenance activity.
- ADR-0020, which picks the library, says whether uPlot stays for dense raw drilldowns, and sets the chart-chunk budget.
- [ADR-0010](../../adr/0010-sveltekit-static-spa.md) marked as amended, and [frontend#technology](../../architecture/frontend.md#technology) updated.

## Done when
- The owner accepts ADR-0020.
- The chosen library's chunk loads lazily, and initial JS on every route stays within budget.
