### T14.2.4 follow-up: guide fixes from building `internal/connectors/example/`

The example connector was built from `docs/adapters.md` alone and passes all checks. Apply these to the guide, then tick T14.2.4:

2. Step 4.3: split checks — connector validates the envelope and fields it uses (external key, watermark, cursor); the normalizer warns about record content.
3. Step 7: the `"synthetic": true` marker makes golden bodies differ from stored ones, so normalizers must ignore it; an unparseable case needs `.raw.txt` with a `synthetic: true` line; pin a fixed error message, not json syntax errors (they echo payload bytes).
4. Step 7 snippet uses `Stream`/`Provider` constants that step 2 never declares.
5. Step 8.2: link docs/schema/README.md; `users.password_hash` NOT NULL, connections need `provider_id` (via providers.code), `mode`, `status`; `timezone_periods.valid_from` must precede the samples.

7. Step 8: `dbtest.Migrated` returns `*pgxpool.Pool` but depguard bans pgx outside internal/db — use closures, or add a dbtest helper.
8. Step 8.5: an `AuthNone` connector has no secret; say to use a mutex-guarded buffer logger on both `connectors.Config.Log` and `jobs.Config.Log` and assert no payload values or page tokens appear.
9. Cursor design: every committed page stores `NextCursor`, so `Plan` must resume a cursor holding a page token plus saved server time; the first page's server time travels inside the cursor.
10. Step 4.1: give a body size, mention httpx's 16 MiB default cap, and say an oversized body is not drift.
11. Step 4.2: cover 401/403 for `AuthNone` (permanent), 3xx and non-200 2xx.
12. Step 6: the golden harness sets `ExternalKey` to the case name, so normalizers must not derive keys from it; a record without a device leaves `Device` empty.
