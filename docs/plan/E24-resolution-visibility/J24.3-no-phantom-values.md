# J24.3 No phantom values: capability and daily totals in hours

Epic: [E24 Resolution defaults, opt-in gates and visible data](README.md) · Status: todo · Depends on: None
Read: [resolution#extensions](../../architecture/resolution.md#extensions), [resolution#within-source-aggregation](../../architecture/resolution.md#within-source-aggregation)

**Objective:** A device stands for a metric only if it reports that metric, and a source that reports only daily totals still counts in rules that compose a day from hours.

## Outputs
- **Capability.** A device counts as worn for metric M only if it has rows of M (any kind, daily values included) within `WearLookback`. A new query (modelled on `ResolveWearBuckets` with the daily-value union of `InventoryMetricSources`) is loaded with the wear series in `internal/resolve/load.go` and carried on the wear index; `newWear` assigns only capable devices to rule groups. A group without a capable device is exempt and, with no rows, `no_data`, so the ladder moves on. Pure resolver entry points take capability through the `Series` so tests can pass it.
- **Daily totals in composed days.** `composeDay` (`internal/resolve/extensions.go`) skips daily-only groups hour by hour (never a 0). If the best-ranked group with data for the day is daily-only and ranks above every group that supplied hours, the day is that group's daily value (basis `daily_value`). A daily total is never added to hours.
- Explanations name the case ("only a daily total", "does not report steps").
- `docs/architecture/resolution.md` (wear gate and composition paragraphs) updated.

## Done when
- New synthetic scenarios pass: worn band with heart rate but no metric → no value from it; daily-only band above phone → band's daily total; watch for half a day plus a daily-only band → the watch's hours and the phone's, never the band's total added.
- `TestScenarioHourlyStepsWithWear` and the scenario-04 golden are updated with the reason recorded.
- `vitamux resolve verify` shows no cache/live differences on the synthetic dataset.
