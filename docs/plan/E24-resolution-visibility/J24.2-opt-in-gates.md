# J24.2 Opt-in quality gates and source strip

Epic: [E24 Resolution defaults, opt-in gates and visible data](README.md) · Status: done · Depends on: None
Read: [resolution#extensions](../../architecture/resolution.md#extensions), [resolution#sleep-episode-alignment](../../architecture/resolution.md#sleep-episode-alignment), [frontend#rule-builder](../../architecture/frontend.md#rule-builder)

**Objective:** Coverage and wear gates only apply when the owner asks for them, so a source's reported value is never dropped by a default threshold.

## Outputs
- New built-in versions without `MinCoverage`, `RequireWear` or `MinEpisodeCoverage`: `steps`, `distance_walk_run`, `active_energy`, `resting_heart_rate_nocturnal`, `sleep` (`internal/resolve/builtin.go`), with the version history comment and generated defaults doc updated.
- `internal/resolve/episode.go` stops defaulting the episode coverage to 0.7 when the rule sets none; match overlap stays (alignment, not coverage).
- Rule builder and lens show the gates empty with an "opt-in" hint; owner rules that already set gates keep them.
- Explore metric page: the "Source per day" strip moves behind a toggle, off by default, remembered per viewer (localStorage in try/catch).
- `docs/architecture/resolution.md` and `resolution-defaults.md` describe gates as opt-in.

## Done when
- Built-in shape and defaults-doc tests pass with the new versions; integration scenarios that relied on gates set them explicitly.
- A day where the watch is worn under 80 % resolves to the watch's daily total under the built-in.
- Playwright: the strip is hidden until toggled.
