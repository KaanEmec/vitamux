# J24.1 Default rule and source priority

Epic: [E24 Resolution defaults, opt-in gates and visible data](README.md) · Status: todo · Depends on: None
Read: [resolution#rule-specification](../../architecture/resolution.md#rule-specification), [resolution-defaults#principles](../../architecture/resolution-defaults.md#principles)

**Objective:** No metric is left without a rule. A metric with neither an owner rule nor a built-in resolves through a default rule built from the owner's source order, else a generic device ladder.

## Outputs
- **Source priority setting** `sources.priority`: an ordered list of providers, stored like `dashboard.layout` (`internal/api/dashboard.go`), read and written under `/api/v1/settings`, OpenAPI-first. A Settings card orders the connected providers (drag or arrow keys).
- **Default rule** in `internal/resolve/store.go` `activeSet`: for every catalogue code without a built-in or owner rule, a `Version` with ref `default:<metric>:<n>` (n changes when the source order changes, so the resolved cache, keyed by ref, invalidates).
  - Groups: the owner's providers in order (as `biBrand` groups, relays included), then the generic ladder `watch › band › ring › chest_strap › arm_band › phone › other devices › manual` from the existing helpers in `builtin.go`.
  - Provider-scoped codes get one group: their provider.
  - Window from the catalogue (as `dailyKind` in `internal/api/resolved.go` does), `first_available`, no gates. `basal_energy` and `total_energy` follow `active_energy` (E5) when it has a source.
- `Store.Create` copies a default rule as version 1 on the first edit, as for built-ins. `ListRules` and the Rules page show it with a "Default" badge.
- `noRule` and the `none:` drilldown rule in `internal/api/resolved.go` are removed or reduced to unknown codes.
- Generated `docs/resolution-defaults.md` describes the default rule; `NoBuiltin` reasons now read "uses the default rule".

## Done when
- Every catalogue code resolves on the synthetic dataset; `basal_energy`, `floors_climbed` and every provider-scoped score have values.
- Changing the source order changes the default-rule ref and the resolved values; owner rules and built-ins are unaffected.
- Unit, store integration and API tests cover the default rule; `go run ./internal/resolve/gen` shows no drift.
