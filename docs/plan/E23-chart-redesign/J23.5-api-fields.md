# J23.5 Additive API fields for the new views

Epic: [E23 Charts and metric visualisation redesign](README.md) · Status: done (2026-10-04) · Depends on: None
Read: [api#owner-endpoints-apiv1](../../architecture/api.md#owner-endpoints-apiv1), [resolution#result-shape](../../architecture/resolution.md#result-shape)

**Objective:** Give the new views what they need from the existing endpoints, without new endpoints where a field will do.

## Outputs
Check each item against `api/openapi.yaml`, and add it only if it is missing:
- `GET /resolved/series`: the chosen provider and status for each point, for the tooltip and the source-per-window strip.
- `GET /resolved/sleep`: the episode's bed and wake times plus minutes per stage, for the bedtime chart and the stage stacks.
- `GET /resolved/summary`: the previous-period mean for 7, 30, 90 and 365 days, for the neutral deltas.
- `GET /settings/dashboard`: an additive `hero` list (up to four metrics) in the layout schema.

All changes are OpenAPI-first and additive, and `api.md` and the generated client are updated with them.

## Done when
- `make openapi` shows no drift, Spectral passes, and the integration tests cover each new field on synthetic data.

## Audit result
- Series: `status` and `sources` (rule groups) were present; added `providers` (distinct providers of the chosen groups' sources).
- Sleep: stage time was present as seconds in `result.value` (`sleep_awake`, `sleep_light`, `sleep_deep`, `sleep_rem`); bed and wake were only implicit in `result.window`, so `episode {start, end}` is now explicit.
- Summary: added `compare=true`, which returns `comparisons` (7, 30, 90, 365 days, each with the `previous` period).
- Dashboard: added `hero`.
