# J23.10 Dismissible dashboard alerts

Epic: [E23 Charts and metric visualisation redesign](README.md) · Status: done (2026-10-04) · Depends on: J23.6
Read: [frontend#navigation](../../architecture/frontend.md#navigation)

**Objective:** Let the owner dismiss a dashboard warning or error once they have seen it, without hiding a new problem.

## Outputs
- Each alert has a stable key built from its kind, its subject and the problem's start time or state.
  - Example: reauthentication needed for a connection, since a given time.
  - A new occurrence gets a new key, so it shows again.
- Dismissed keys are stored server-side in the dashboard layout, as an additive `dismissed` list in `GET/PUT /settings/dashboard`.
  - The list is bounded, and keys whose alert is gone are pruned.
  - A dismissal survives a reload and a second browser.
- A dismiss button on every alert, with `aria-label`, and an "n dismissed · Show" link that shows them again.
- Dismissing hides the alert on the dashboard only. Connections and Settings still show the state.

## Done when
- Integration tests cover the new field. Playwright covers dismissing, reloading, a new occurrence reappearing, and "Show".
