# J19.2 WHOOP sidecar and sign-in

Epic: [E19 WHOOP connector](README.md) · Status: in progress · Depends on: J19.1, J17.2, J17.3
Read: [connectors#remote-sidecar-mode](../../architecture/connectors.md#remote-sidecar-mode), [connectors#typed-errors](../../architecture/connectors.md#typed-errors), [security#threat-model](../../architecture/security.md#threat-model)

**Objective:** A stateless Node sidecar that wraps `@dofek/whoop`, signs a user in with MFA, and refreshes their session.

## Outputs
- `sidecars/whoop/` in the [J17.4 layout](../E17-sidecar-connectors/J17.4-third-party-packaging.md): Node ≥ 22.14 LTS, `package.json` plus `package-lock.json`, Dockerfile on a digest-pinned base, non-root, read-only root filesystem, 256 MiB limit, healthcheck, `UPSTREAM.md` (repo and package path, license MIT, unofficial).
- `describe`: provider `whoop`, `Official=false`, `AuthKind=InteractiveMFA`, streams from [J19.3](J19.3-streams.md), rate limits from J19.1, and the upstream version.
- `auth/begin` (email and password) → an MFA step (app or SMS) or success; `auth/continue` (code) → credentials; `auth/refresh` with a rotated refresh token returned to the core. Credentials are sealed by the core. The password and the MFA session pass through only and are never stored or logged.
- Error mapping: refused or expired tokens → `reauth_required`; `WhoopRateLimitError` → `rate_limited` with its `retryAfterSeconds`; network and 5xx → `transient`; a `zod` validation failure or unexpected shape → `schema_drift`; anything else → `permanent`.
- Sidecar tests on synthetic cassettes, plus a replay mode that serves J19.1 fixtures for the conformance kit and the core's lifecycle tests.

## Done when
- The sidecar passes `vitamux connector-test` for describe, auth (app MFA, SMS MFA, wrong code), refresh with rotation and every error class.
- The redaction audit, extended with a sentinel WHOOP password, MFA code, MFA session and tokens, finds no hits.
