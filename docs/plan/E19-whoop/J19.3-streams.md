# J19.3 Streams, planning and backfill

Epic: [E19 WHOOP connector](README.md) · Status: in progress · Depends on: J19.2, J06.6
Read: [connectors#runtime-responsibilities](../../architecture/connectors.md#runtime-responsibilities), `docs/providers/whoop.md` (written in J19.1)

**Objective:** Fetch every WHOOP data family incrementally and backfill history within WHOOP's limits.

## Outputs
- Streams (names final after J19.1), each with a default schedule, correction lookback, unit size and max backfill:
  - `whoop.heart_rate`: 6-second step by default, configurable
  - `whoop.steps`
  - `whoop.cycles`: strain and recovery
  - `whoop.sleep`
  - `whoop.workouts`: developer workouts, plus weightlifting detail when present
  - `whoop.strain_deep_dive`: raw only
  - `whoop.journal`: raw only, off by default
- Plan: time windows sized so a 6-second HR page stays within limits; cycles, sleep and workouts paged by their next token; a lookback that covers recovery and sleep rescoring.
- Pacing from `WHOOP_API_THROTTLE_MS` and J19.1's limits. Backfill is slow by default, resumable and cancellable.
- Raw lines carry each response verbatim, with the endpoint and parameters in `request`.

## Done when
- A synthetic-year backfill, then incremental runs, has no gaps or duplicates; a re-fetched unchanged window is a no-op.
- A rescored sleep or recovery inside the lookback creates a new raw version.
- An interrupted backfill resumes where it stopped.
