# J22.25 Apple Health source filter: take or ignore per app and type

Epic: [E22 Vitamux iOS app](README.md) · Status: done · Depends on: J22.3, J22.14, J22.16; J22.13 for the panel side
Read: [ios-app#apple-health](../../architecture/ios-app.md#apple-health), [apple-health#origins-and-relays](../../architecture/apple-health.md#origins-and-relays), [resolution-defaults](../../architecture/resolution-defaults.md)

**Objective:** The owner decides, in one plain screen, which apps' data Vitamux takes from Apple Health and which it ignores, per app and optionally per type, so a provider connected directly (WHOOP, Garmin) is never collected a second time through its copy in Apple Health.

Owner decision (2026-10-04): the relayed-origin handling at resolution time is not enough; a visible take/ignore setting is required.

## Outputs
- **Server:** a per-device source filter stored with the device (`devices.source_filter`, versioned JSON): a list of origin apps (bundle id, display name) each set to `take`, `ignore` or `per_type` with a type list. `GET /api/ingest/v1/devices/self` returns it with a version, so the phone applies it like anchor-reset requests. `PUT /api/v1/devices/{id}/source-filter` changes it from either client and is audited. Changing an app from `ignore` to `take` queues an anchor reset for the affected types, so its history is pulled.
- **Defaults:** Apple's own sources (`com.apple.health.*`, the Watch and iPhone) are `take`. An origin in `known_relay_origins` whose provider has an active direct connection defaults to `ignore`, with the reason shown ("You get WHOOP directly; its copy in Apple Health would count twice"). Connecting or deleting a direct connection later re-evaluates the default, but never changes an explicit owner choice. Everything else is `take`.
- **Kit:** `HKSourceQuery` discovers the apps that have written each enabled type; anchored queries carry `HKQuery.predicateForObjects(from:)` built from the filter, so ignored data never leaves the phone. A changed filter bumps the type's anchor as required. Watch-side extensions that report a different bundle id are matched by their parent app where HealthKit exposes it, and otherwise listed on their own.
- **App:** an **Apple Health › Sources** screen (reached from the Apple Health screen and from the Sources tab): one row per app seen in Health with its icon tile, what it writes (types and last sample), a Take / Ignore control, and "Choose types…" for the per-type case. Rows that are ignored by default explain why in one line. A row's link opens Explore filtered to that origin.
- **Panel:** the same screen under Settings › Devices, per paired iPhone, built with the E21 kit. The existing origin classification (native, relayed, direct) stays and is shown on the same row.
- **Server-side guard:** rows that still arrive from an ignored origin (an old app build, a race with a filter change) are kept raw and marked `ignored_by_filter`, not normalized, so the raw-first rule holds and nothing is silently lost. Explore and the all-sources view hide them by default, with an "ignored sources" toggle.
- Docs: [apple-health](../../architecture/apple-health.md) origins section and the app and panel user guides.

## Done when
- Device test: with WHOOP connected directly and the WHOOP app writing to Health, a fresh pairing shows WHOOP as "Ignored by default", no WHOOP rows arrive through `apple_health`, and the resting-heart-rate rule shows only the direct WHOOP source. Switching it to Take pulls WHOOP's Health history and the relayed exclusion in the rules still applies.
- Unit tests (kit): the predicate matches the filter; a filter change resets the right anchors; an unknown source is taken by default.
- Integration tests (server): default evaluation on connect and delete, audit entries, `ignored_by_filter` rows kept raw and hidden.
- UI tests in both clients for take, ignore, per-type and the explanation line.

## Notes
- Server: `internal/sourcefilter` (decision, defaults, diff), migration 00046 (`clients.source_filter`, `source_filter_version`, `health_sources`; `ignored_records`), `internal/api/sourcefilter.go`, the guard in `internal/normalize/ignore.go`. "devices.source_filter" lives on `clients`, the table paired devices are rows of. Defaults are evaluated on every read, so connect, disable and delete re-evaluate them without a trigger; the version counts explicit changes only.
- Kit: `SourceFilter` (HealthBridgeCore), `HealthStore.sources(for:)`, `lastSampleDate`, and `anchoredPage(…, excluding:)` without a default, so every wrapping store forwards it. The predicate is NOT(ignored sources), not "from the taken sources", so a new app is never skipped past the anchor. `GatedStore` now also forwards the registry v2 detail reads it was missing.
- App: `Features/AppleHealth/Sources`, `vitamux://apple-health/sources`, `vitamux://explore?origin=`. The Sources tab link belongs to [J22.11](J22.11-sources.md), which was rebuilding that tab at the same time.
- Panel: `/settings/devices/{id}/sources`; Explore takes `?origin=` and has an "Ignored sources" toggle, as do the metric and day pages.
