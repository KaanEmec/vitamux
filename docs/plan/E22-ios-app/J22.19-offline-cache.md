# J22.19 Offline read cache

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.4
Read: [ios-app#offline-cache-widgets-and-notifications](../../architecture/ios-app.md#offline-cache-widgets-and-notifications)

**Objective:** The app opens and shows the last data it saw without a network, clearly marked, and never keeps more than it should.

## Outputs
- A small file cache in VitamuxKit's `Core/` (one type, no database): GET responses for an allow-list of endpoints (dashboard layout and summary, inventory, metric ranges, specialised views, lab results, connections), keyed per server, user and request, in the app group container with file protection `completeUntilFirstUserAuthentication`.
- Stale-while-revalidate in the client: cached first, then fresh; screens show "as of <time>" and an offline banner. Mutations need the network and say so.
- A fixed 100 MB cap; the oldest files go first. It never caches PDFs, secrets, API-key or recovery-code responses, or exports.
- Cleared on sign-out, server change, `401` and from preferences; excluded from iCloud backup.

## Done when
- Tests: offline launch to a cached dashboard; eviction at the cap; nothing cached outside the allow-list; sign-out empties it.
