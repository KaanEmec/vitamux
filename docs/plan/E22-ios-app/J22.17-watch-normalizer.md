# J22.17 Server: Watch data normalizer, storage and endpoints

Epic: [E22 Vitamux iOS app](README.md) · Status: done · Depends on: J22.15
Read: [ios-app#apple-watch](../../architecture/ios-app.md#apple-watch), [apple-health#payload](../../architecture/apple-health.md#payload), [data-model](../../architecture/data-model.md), [ADR-0004](../../adr/0004-blob-store.md)

**Objective:** Every Watch type the phone sends is stored raw, normalized with provenance, and readable through the API.

## Outputs
- **Catalogue:** the ADR-0024 codes added to `internal/catalog` with a new seed marker (quantities, `rr_interval` marked not resolvable, event codes for ECG, rhythm alerts, mind, cycle tracking and symptoms), and their rows moved out of [metric-catalog](../../architecture/metric-catalog.md) into the generated [metrics.md](../../metrics.md).
- **Migration:** `health_events.file_blob_sha256`, referenced like `workouts.file_blob_sha256`; `workout_segments.kind` adds `activity`, `pause` and `marker`.
- **Normalizer** (`internal/connectors/applehealth`, new normalizer version): quantities to `measurements`; beats to `rr_interval` samples; ECG to an event with its waveform blob; routes to `workout_route` events with their blob, found from the workout by `workout_uuid` whatever the arrival order ([ADR-0024](../../adr/0024-watch-data.md#storage-no-new-tables)); workout events and activities to `workout_segments`; activity summaries to daily values with goals in `context`; State of Mind and cycle tracking to `health_events`. Deletions tombstone as in v1.
- **Endpoints:** `GET /events/{id}/waveform`, `GET /workouts/{id}/route`, in the spec, the authz matrix and the generated reference.
- **Lifecycle:** exports, `purge-user`, deletion and the blob sweep cover the new blobs; raw retention leaves them alone while a canonical row references them.
- The [export importer](../../architecture/apple-health.md#export-importer-fallback) maps the export records of the new types where the export has them.

## Done when
- Normalizer tests on the J22.15 fixtures: each type, a deletion, a reprocess with no changes, a route that arrives before its workout, a changed summary day replacing the old one.
- `TestAuthzMatrixEnforced` covers the new endpoints.
- No health value appears in logs, checked by the existing redaction tests.

## Notes
- The goals of an activity summary and an effort score's workout link need a `context` on measurements, which had none: migration 00044 adds `measurements.context` (nullable jsonb) beside the two changes above. `rr_interval` is `Unresolved` in the catalogue (no rule, windows or strategies) and has no default rule.
- Normalizer version 4 (`healthkit.samples`), export normalizer version 2. Identifiers as HealthBridgeKit sends them (J22.16): State of Mind `HKDataTypeStateOfMind`, ECG metadata `HKMetadataKeyAppleECGAlgorithmVersion`; a single-activity workout stores no activity segment.
- Blob documents travel in `normalize.Output.Files`; the writer stores them in the event's transaction and every row naming a blob holds one reference (workout files included), released by `prune_superseded`, connection deletion and `purge-user`. Exports carry them in `blob_content.ndjson` even without `include_raw`.
- The export importer maps the new record types; ECG CSVs, route GPX files and `ActivitySummary` elements stay unread ([apple-health](../../architecture/apple-health.md#export-importer-fallback)).
