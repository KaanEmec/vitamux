# J22.5 App project, shell, sign-in and Bridge migration

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.2, J22.4
Read: [ios-app#server-and-sign-in](../../architecture/ios-app.md#server-and-sign-in), [ios-app#navigation](../../architecture/ios-app.md#navigation), [apple-health#distribution](../../architecture/apple-health.md#distribution)

**Objective:** The app exists, signs in to a chosen server, and has the navigation every other screen plugs into.

## Outputs
- **Project:** `apple/VitamuxApp/project.yml` (xcodegen), grown from HealthBridgeApp, laid out as in the J22.1 skeleton (one folder per feature, `AppState`, `Route`): app target named Vitamux, widget extension stub, UI test target, app group and Keychain access group, privacy manifest. Bundle id and Keychain service stay Bridge's so an installed Bridge upgrades in place. `apple/HealthBridgeApp` is removed once J22.14 has moved its screens.
- **Server step:** URL field or QR scan, `system/version` check, plain errors (unreachable, not Vitamux, too old, http refused).
- **Sign-in:** username and password, then a TOTP or recovery code on `totp_required`, rate-limit wait from `Retry-After`, "session expired" on return.
- **Shell:** tab bar (Dashboard, Explore, Sources, Lab, More), global search over sections, settings pages, connections, metrics and rules (`GET /metrics`), sync status from `GET /connections`, theme preference, sign-out (with "also unpair this iPhone").
- **Router:** `vitamux://` deep links for every screen in the J22.1 map.
- **App lock:** optional Face ID or passcode on launch and after a timeout; blurred app-switcher snapshot.

## Done when
- UI tests on the fake server: first run to dashboard; TOTP and recovery code; wrong password and rate limit; session expiry mid-use; sign-out; deep link to a metric; app lock.
- Installing the app over a Bridge build on a simulator keeps the paired device token and anchors.
