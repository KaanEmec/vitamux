# J22.11 Sources: connections, connect and guided setup

Epic: [E22 Vitamux iOS app](README.md) · Status: done (2026-10-05) · Depends on: J22.3, J22.5; E20 (J20.2–J20.5) for the setup wizards
Read: [connectors#oauth-connection-flow](../../architecture/connectors.md#oauth-connection-flow), [connectors#source-setup-in-the-web-panel](../../architecture/connectors.md#source-setup-in-the-web-panel), [ios-app#connecting-sources-from-the-phone](../../architecture/ios-app.md#connecting-sources-from-the-phone)

**Objective:** Every source can be watched, fixed and connected from the phone, including OAuth and MFA sign-ins.

## Outputs
- **List** (`/connections`, `/connections/{id}/backfills`, `/runs`, `/providers`): summary line, a "This iPhone" card (J22.14), one card per connection with health, last sync, 14-day run strip, fix-it action and Sync now; backfills in progress; recent runs; result banners from the `vitamux://connections?…` return.
- **Connect:** providers re-fetched each time; unavailable sidecars disabled; the unofficial badge; E20 setup states (`needs_app_credentials`, `needs_sidecar`, `ready`, `managed_by_environment`) with the Withings app-credential wizard and the sidecar card; OAuth through `ASWebAuthenticationSession` with `return: app`; prompt steps (text, password, code) that clear values once sent and restart on error.
- **Detail tabs:** overview (run strip, facts); streams (health, cursor, schedules, reset cursor); devices (`/source-devices`: type, name, merge with its confirmation); backfills (start with stream and range, per-unit progress, retry, cancel, 5 s polling); history (paged); settings (pause or resume, schedule interval and on/off, delete keeping or deleting data). Reauthorize and Sync now in the header.

## Done when
- UI tests on the fake server for every tab and action, including each `auth_error` code.
- Against the stack smoke (J22.22): a Withings connection through `fakeprovider` completes on a simulator and returns to the app.
- A prompt-step flow with an MFA code completes against a fake sidecar.

## Notes
- Code: `apple/VitamuxApp/Sources/Features/Sources` (`SourcesView` and `SourcesModel` for the list, banners and "This iPhone"; `ConnectionCard` with `ActionsRow`; `RunStrip`; `ConnectSheet` with the setup states and sidecar card; `AppWizardView`; `AuthFlow` for the auth browser, Sync now and Reauthorize, and prompt steps) and `Detail/` (one file per tab, each loading its own data; backfills poll with `Poller.backfills` while one runs and the tab is visible).
- OAuth: auth/begin always sends `{"return": "app"}`; the redirect opens in SwiftUI's `webAuthenticationSession` (ephemeral, callback scheme `vitamux`) and its `vitamux://connections?…` return goes through the router, so a reauthorization from the detail ends on Sources with the banner, as in the panel. Cancelling the browser is not an error.
- Device types and names can be set but not cleared: the generated client omits nil fields, so it cannot send the merge patch's `null` (`SourceDevicePatch`).
- Fixtures: `FakeServer+Sources.swift` (now the one owner of `GET /connections`, still Withings healthy and Garmin needing reauthorization), checked by `SourcesFakeTests`; its `authorize(_:)` plays the auth browser in UI tests, and `-uitest-withings-env` sets the Withings app credentials by the environment. UI tests: `SourcesUITests` (list, every `auth_error` code, the Withings wizard through OAuth, credentials of the environment, WHOOP's sidecar and a prompt flow with an MFA code, reauthorization by prompt and by OAuth) and `ConnectionDetailUITests` (every tab and action).
- Left for J22.22 and J22.23: the stack smoke of a Withings connection through `fakeprovider` on a simulator, and a real `ASWebAuthenticationSession` sign-in on a device.
