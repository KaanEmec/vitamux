# J22.12 Lab documents, review and results

Epic: [E22 Vitamux iOS app](README.md) · Status: done (2026-10-05) · Depends on: J22.5, J22.6
Read: [lab-documents](../../architecture/lab-documents.md), [ADR-0013](../../adr/0013-extraction-consent.md)

**Objective:** Get a blood-test PDF into Vitamux from the phone and review it row by row with the page beside it, with the same consent and confirmation rules as the panel.

## Outputs
- **Intake:** Files picker, share-sheet import (an action extension or "Open in Vitamux"), and a VisionKit document scan saved as one PDF; checked against 20 MB before upload (`POST /documents`, multipart). A `200` says "already stored". Scans never leave the app except to the owner's server.
- **Documents** (`/documents`, `/extractors`): status, Extract (provider and model consent for external AI, none for the test extractor), Review, Open, Delete keeping or deleting results.
- **Review** (`/documents/{id}`, `/file`, `/extractions`, `/extractions/{id}`): PDFKit page with the selected row's evidence box outlined; row list with label, value and unit as printed, confidence and checks; row editor (value, unit, comparator, analyte with alias suggestion from `/analytes/aliases`); accept as read, save and accept, reject (`PATCH …/rows/{row}`, changed fields only); confirm with "go to row" for unreviewed ones, confirm again, unconfirm; extract again; 2 s polling while a run is active.
- **Results** (`/lab-results`, `/{id}/history`): by analyte or printed label, newest first, as printed, with history and a link to the analyte view.
- The PDF is shown from memory and not kept in the cache.

## Done when
- UI tests: upload from Files, scan (with a fixture image), consent required for an external provider, accept, edit, reject, confirm with an unreviewed row, unconfirm, delete.
- No extracted value appears in logs.

## Notes
- Code: `apple/VitamuxApp/Sources/Features/Lab`: `LabView` (documents), `Intake` (Files, scan, upload), `ExtractSheet` (consent), `ReviewView`/`ReviewModel`, `PDFPageView` (PDFKit, the evidence box as a square annotation), `RowEditor` (a medium-detent sheet, so the PDF page and its outline stay in view, as the panel's side pane), `ResultsView` (with the history sheet), `LabImportView`, `LabFormat` (the panel's wording). Results link to the J22.9 analyte view.
- Share sheet: "Open in Vitamux" (`CFBundleDocumentTypes` for PDF; iOS copies the file to the Inbox, which is deleted after upload); a `file://` URL parses into `Route.labImport`. No action extension.
- Scans become one JPEG-compressed PDF in memory (PDFKit), never written to disk; the PDF under review is held in memory only (`no-store`, not in the J22.19 cache). The feature logs nothing.
- The generated client drops nil fields, so the row editor cannot clear a field to `null` (merge patch); it says so and points to the panel. Fixing it needs a nullable patch in the kit or spec.
- UI tests cannot drive the system Files picker or the document camera: under `-uitest` they return the synthetic fixture PDF (`FakeServer.syntheticLabPDF`; `-uitest-large-pdf` for one over 20 MiB) and a synthetic page image. The real picker, camera scan and "Open in Vitamux" are device checks for J22.23.
- Fixtures: `FakeServer+Lab.swift` (a run finishes on the second poll, so the 2 s poller runs), checked by `LabFakeTests`; UI tests in `LabUITests`, including a judgement-word check. GET /lab-results stays with `FakeServer+Specialised.swift`, so results confirmed in the fake do not appear in the results list.
