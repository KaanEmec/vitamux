# J22.16 HealthBridgeKit: type registry v2 and Watch readers

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.15
Read: [ios-app#apple-watch](../../architecture/ios-app.md#apple-watch), [apple-health#sync-algorithm](../../architecture/apple-health.md#sync-algorithm)

**Objective:** The kit reads and uploads every Apple Watch type from ADR-0022 with the same anchors, retries and idempotency as v1.

## Outputs
- `Registry.v2`: the v1 types plus the new ones, the new groups, and per-type page sizes. v1 stays a subset, so upgraded installs keep their anchors.
- Readers that add the extra detail to a page before upload: ECG voltages, heartbeat series, route locations linked to their workout, workout events and activities, State of Mind fields. Each stays behind the existing `HealthStore` protocol so the fakes cover it.
- Activity summaries: a date-range read of the last 7 days on each sync, with UUIDv5 keys and no anchor.
- Authorization requested per group, including the series types (`HKSeriesType.heartbeat()`, `workoutRoute()`) and the ECG type.
- Background delivery registered for the new sample types where iOS allows it.

## Done when
- `swift test` covers each new reader with fakes: paging under the batch limit, deletions, a route arriving before its workout, a re-read summary day.
- Batches built from the new fixtures validate against the extended schema.
