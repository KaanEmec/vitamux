# J22.4 VitamuxKit: generated client, core and fake server

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.1
Read: [ios-app#api-client](../../architecture/ios-app.md#api-client), [api#conventions](../../architecture/api.md#conventions)

**Objective:** One tested Swift package that every screen uses to talk to a Vitamux server.

## Outputs
- `apple/VitamuxKit` (Swift 6, iOS 18, macOS 15 for tests): one library target and one test target, with folders:
  - **`API/`:** swift-openapi-generator build plugin over a symlink to `api/openapi.yaml` (ingest tag excluded), `URLSession` transport. Nothing generated is committed.
  - **`Core/`:** `ServerProfile` (URL validation, https rule, debug exceptions), `SessionStore` (Keychain, access group), one middleware for bearer auth, `Problem` and field pointers, `429` with `Retry-After`, `401` handling; a `Poller` that runs only while observed; date helpers for local dates and the owner's timezone.
- **Fake server:** a `URLProtocol` stub with synthetic fixtures per endpoint, mirroring `web/e2e/fake-api.ts`. Unit tests use it directly; the app's debug build switches to it under `-uitest` for UI tests. No separate testing target.
- If the plugin refuses the symlink, fall back to a copy from `make openapi` with a CI drift check, and record why.
- CI: the `swift` job also runs `swift test --package-path apple/VitamuxKit`.

## Done when
- Unit tests cover login with TOTP, a problem with field errors, a rate limit, an expired session, cursor paging, and the poller stopping.
- The generated client compiles against the full spec with no hand edits.
