# J22.4 VitamuxKit: generated client, core and fake server

Epic: [E22 Vitamux iOS app](README.md) · Status: done (2026-10-05) · Depends on: J22.1
Read: [ios-app#api-client](../../architecture/ios-app.md#api-client), [api#conventions](../../architecture/api.md#conventions)

**Objective:** One tested Swift package that every screen uses to talk to a Vitamux server.

## Outputs
- `apple/VitamuxKit` (Swift 6, iOS 18, macOS 15 for tests): one library target and one test target, with folders:
  - **`API/`:** swift-openapi-generator build plugin over a symlink to `api/openapi.yaml` (ingest tag excluded), `URLSession` transport. Nothing generated is committed.
  - **`Core/`:** `ServerProfile` (URL validation, https rule, debug exceptions), `SessionStore` (Keychain, access group), one middleware for bearer auth, `Problem` and field pointers, `429` with `Retry-After`, `401` handling; a `Poller` that runs only while observed; date helpers for local dates and the owner's timezone.
- **Fake server:** a `URLProtocol` stub with synthetic fixtures per endpoint, mirroring `web/e2e/fake-api.ts`. Unit tests use it directly; the app's debug build switches to it under `-uitest` for UI tests. No separate testing target.
- If the plugin refuses the symlink, fall back to a copy from `make openapi` with a CI drift check, and record why. **Taken** (see Notes).
- CI: the `swift` job also runs `swift test --package-path apple/VitamuxKit`.

## Done when
- Unit tests cover login with TOTP, a problem with field errors, a rate limit, an expired session, cursor paging, and the poller stopping.
- The generated client compiles against the full spec with no hand edits.

## Notes
- **Copy, not symlink.** The plugin read the symlink fine, but swift-openapi-generator 1.13 rejects `{type: 'null'}` inside `oneOf` and drops the whole property, so closed objects (`additionalProperties: false`, e.g. `SourceRef.device`) fail to decode real responses. `apple/VitamuxKit/copy-openapi.sh` (run by `make openapi`) copies the spec and rewrites each nullable reference to `$ref` plus `type: ['null']` (an inline object to `type: [object, 'null']`), which the generator reads as optional; it fails on any null form it does not know. CI's `swift` job checks the copy is current. No generated Swift is committed and nothing is hand-edited.
- **Kit surface.** `Client(profile:sessions:urlSession:onExpired:)` with one `SessionMiddleware`: bearer only to the issuing server, every status of 400 or more thrown as `Problem` (status, code, field pointers, `retryAfter`), `401` on a request that carried the token clears the store and calls `onExpired`. The kit never retries a 429; the screen shows the wait. Instants decode with or without fractional seconds (`RFC3339DateTranscoder`).
- **`-uitest`.** The app's debug build uses `FakeServer.uiTest` (host `fake.vitamux.test`) with `SessionStore.inMemory()` when `FakeServer.isUITestRun`; J22.5 wires it into `AppState`. `FakeServer` is debug-only. Fixtures: sign-in (password, TOTP, recovery, validation, lockout), logout, session, sessions, version, timezone periods, paged measurements; other `/api` paths answer 404.
- **Dependencies** pinned in `Package.resolved` (generator, runtime, URLSession, HTTP types and their OpenAPIKit, Yams, algorithms, argument-parser, collections, numerics); CI diffs the list.
- `xcodebuild` needs `-skipPackagePluginValidation` (or "Trust & Enable" once in Xcode) for the plugin.
