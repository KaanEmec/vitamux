# J22.14 Apple Health in the app

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.3, J22.5
Read: [apple-health](../../architecture/apple-health.md), [ios-app#apple-health](../../architecture/ios-app.md#apple-health), [ADR-0014](../../adr/0014-healthkit-contract.md)

**Objective:** The app is the iPhone's Apple Health bridge: pairing in one tap, the same incremental and background sync as Bridge, and one screen showing both the phone's and the server's view.

## Outputs
- **Embedding:** HealthBridgeKit's Core and HealthKit modules wired into the app delegate: observer queries and `enableBackgroundDelivery` registered in `didFinishLaunching`, `BGAppRefreshTask`, completion handlers always called. The contract, payload and anchor rules are unchanged.
- **One-tap pairing:** signed in, "Sync Apple Health from this iPhone" creates and redeems a pairing code; the device token goes to its own Keychain item. Manual QR or code pairing stays for a sync-only phone.
- **Apple Health screen:** metric groups with on-demand authorization ("requested", never "granted"), per-type anchor, last upload, queued batches and errors, history pull progress, Sync now, local anchor reset, server-requested resets applied, possibly-denied hints from `GET /devices`, privacy text, unpair (revoke and forget the token).
- **Sources link:** the screen opens the Apple Health › Sources filter ([J22.25](J22.25-apple-health-source-filter.md)) and shows how many apps are taken and ignored.
- **Separation:** sign-out leaves sync running unless the owner also unpairs; a revoked device token stops sync with a clear state and a re-pair button.
- **Migration:** Bridge's screens and `apple/HealthBridgeApp` removed; a Bridge install upgrades without re-pairing or a full re-pull.
- HealthBridgeKit additions only where needed (status snapshot API, pairing helper), with tests. Registry v2 and the Watch types come from [J22.16](J22.16-watch-kit.md); this screen lists their groups once it lands.

## Done when
- UI tests with the fake HealthStore and fake server: one-tap pairing, enabling a group, sync now, a revoked token, a server-requested reset, unpair.
- `swift test` for HealthBridgeKit still passes; ingest integration tests unchanged.
- The device campaign (J22.23) confirms background delivery and the Bridge upgrade on a physical iPhone.
