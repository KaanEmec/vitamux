# J22.2 Backend: bearer app sessions

Epic: [E22 Vitamux iOS app](README.md) · Status: todo · Depends on: J22.1
Read: [ios-app#server-and-sign-in](../../architecture/ios-app.md#server-and-sign-in), [security#owner-sign-in](../../architecture/security.md#owner-sign-in), [security#authorization](../../architecture/security.md#authorization)

**Objective:** The app signs in with the owner's password and TOTP and gets a revocable bearer session that behaves like a browser session everywhere except transport.

## Outputs
- **Migration:** `sessions.kind` (`browser` | `app`) and `sessions.name`; existing rows are `browser`.
- **Login:** `POST /api/v1/auth/login` accepts `{"client": "app", "device_name": …}` and answers `{user, token, expires_at}` with no cookie. Throttling, `totp_required`, recovery codes and audit are unchanged.
- **Token:** `vmx_ses_<id>_<secret>`, stored as SHA-256 like cookie sessions; lifetimes from `VITAMUX_APP_SESSION_IDLE` (default 30 days) and `VITAMUX_APP_SESSION_MAX` (default 90 days) in [configuration](../../configuration.md).
- **Access:** `internal/api/access.go` resolves a bearer `vmx_ses_` token to a `session` principal; bearer requests skip CSRF. API keys and client tokens are unchanged and still never reach session-only routes.
- **Sessions API:** `GET /auth/sessions` returns `kind` and `name`; `DELETE /auth/sessions/{id}`, `POST /auth/logout` and password change end app sessions too (password change ends every other session, app ones included).
- **Panel:** Settings › Security shows the kind and the device name.
- `api/openapi.yaml`, `api/authz.yaml` and `docs/api-reference.md` updated.

## Done when
- `TestAuthzMatrixEnforced` calls every route with an app session too, with and without CSRF, and gets the same answer as a browser session (CSRF not required).
- Integration tests: login with TOTP; idle and absolute expiry; revoke from the panel gives `401` on the next request; password change ends app sessions; logs and audit hold no token.
