# J22.10 Rules, rule lens and rule builder

Epic: [E22 Vitamux iOS app](README.md) · Status: done · Depends on: J22.8
Read: [frontend#rule-builder](../../architecture/frontend.md#rule-builder), [resolution#rule-specification](../../architecture/resolution.md#rule-specification), [resolution#strategies](../../architecture/resolution.md#strategies)

**Objective:** The owner can see and change how every metric is resolved from the phone, with a preview before saving.

## Outputs
- **Draft model:** a Swift twin of `web/src/lib/rules/rule.ts` that builds and validates a `vitamux.rule/1` spec, tested against `schemas/resolution-rule.v1.json` and the same plain-sentence cases as the web.
- **Catalogue** (`/rules`, `/metrics`, `/coverage`): one row per metric with the rule in plain words, source order and the 90-day coverage heatmap; search; All, Custom and Built-in filter.
- **Rule page** (`/rules/{metric}/versions`, `/activate`): rule in effect, coverage filtered by origin, version timeline, activate any version, compare any two.
- **Rule lens:** a bottom sheet over the metric chart (J22.8): reorder source groups, exclusion chips, strategy, window and minimum coverage limited to what `/metrics/{code}` allows, the sum warning to acknowledge, debounced `POST /resolution/preview` drawn as a ghost series with changed windows marked and a summary; save, save and activate, revert, history.
- **Builder:** the five steps, one screen each: metric; sources with selector suggestions (`/origins`, `/source-devices`) and the relay-exclusion shortcut; strategy cards; window and quality; review with diff and 14-day preview. Server field errors return to their step and control.

## Done when
- UI tests: reorder, preview, save and activate, revert; an unacknowledged sum cannot be saved; a field error points to its control; activating an old version.
- A rule saved on the phone is byte-identical in spec to the same rule saved in the panel.

## Notes
- The draft model lives in VitamuxKit (`Core/RuleForm.swift`, `RuleText.swift`, `JSONValue.swift`) so `swift test` checks it against `fixtures/rule-model.json` (written from the panel's `rule.ts` and `sentence.ts`, also checked by `web/e2e/rule-model.spec.ts`) and the schema; specs keep the panel's key order and whole numbers stay integers.
- The rule lens opens from "Edit rule" on metric detail and from the rule page; its preview chart draws the draft as a ghost over the rule in effect, with the changed days marked.
