# J22.22 Quality gates and CI

Epic: [E22 Vitamux iOS app](README.md) · Status: done (2026-10-07) · Depends on: J22.7–J22.21
Read: [project#testing-levels](../../architecture/project.md#testing-levels), [E21 J21.13](../E21-visualisation/J21.13-quality-release.md)

**Objective:** The app is held to the same bar as the panel: tested on every screen, accessible, fast, and private.

## Outputs
- **CI:** the `swift` job runs both packages' tests, the allowed-package check (`Package.resolved` holds only Apple's swift-openapi packages), an `xcodebuild` of the app and widget for the simulator, and the UI test suite on the fake server.
- **Stack smoke:** `make test-ios-stack` starts a real server on a throwaway database with synthetic data (as `scripts/e2e-stack.sh` does) and runs a simulator flow: server step, sign-in with TOTP, dashboard, a metric, an override, a fake Withings connection, sign-out.
- **Parity review:** the [parity matrix](../../architecture/ios-app.md#parity-matrix) is ticked row by row against the app, and any panel feature added since J22.1 gets a row.
- **Lean review:** the code is checked against the [lean architecture](../../architecture/ios-app.md#lean-architecture) rules; any layer, package or abstraction that crept in is removed or justified in ADR-0023.
- **Accessibility:** VoiceOver labels and order, the largest accessibility Dynamic Type size, Reduce Motion, Increase Contrast, and status never by colour alone; a `performAccessibilityAudit()` UI test per screen.
- **Performance:** signposts for dashboard ready and chart render; dashboard under 1 s and a 14,400-point day without dropped frames on the synthetic 3-year dataset.
- **Privacy:** a test runs the UI suite with synthetic values and scans the unified log for them and for tokens; the privacy manifest is validated.

## Done when
- CI is green with every gate above.
- No serious accessibility audit failures on any screen.

- Accessibility: no description, trait or attributable element-detection issue on any screen. The first survey (2026-10-06) found 72 hit regions under 44 pt on 16 screens; the shared `tapTarget()` and `.iconTapTarget` (VitamuxKit `Charts/TapTarget.swift`) size them all, and a control's hit region now fails the audit. Two non-control nodes stay reported: a Day-view chart's hour column and a workout's static rule tag. Contrast, clipped text and Dynamic Type stay reported.
- Fake-server drift found by the stack smoke is fixed: the fake names resting heart rate `resting_heart_rate`, as the catalogue.
- The two `WatchUITests` failures were the date seam: the app took "today" from the device's zone and the fake from `Europe/Berlin`, so in the hour or two a day when the dates differ, ranges and day links missed the fixtures. Under `-uitest` the app now runs in the fake's zone (`FakeServer.timeZone`) and tests write dates with `Fake.day`; the date-sensitive classes pass with the fake a day behind the host.
- Lean review: one shared `Format` (Shared/Format.swift) replaced near-duplicate formatters (`SettingsFormat.when`/`ago`/`provider`, `DashboardAlert.ago`, `SourcesCopy.day`/`plural`, `LabText.plural`, `NotificationContent.day`, the number parsers of the override sheet and row editor, `CardContent.groupLabel`, `AppleHealthView.relative`, `LabResult.printedValue`'s own comparator logic); what stays on purpose is in [ADR-0023](../../adr/0023-ios-app.md#decision). Parity: rows added for the Watch views and J24.5; analyte-code suggestions are out of scope.
- The privacy-manifest check added the file-timestamp reason (C617.1) the offline cache needs.
- The log scan leaves out two system sources inside the app process: XCTest's agent (`com.apple.dt.xctest`, test-only) and the accessibility runtime (`com.apple.Accessibility`), which logged an override's label (its note) at info level when a notification post failed under XCUITest. Info lines are not persisted on a device; re-check with VoiceOver in J22.23.
- Local run, 2026-10-07 (iPhone 17 Pro, iOS 26.5, `ui-gates.sh` in four class batches): VitamuxKit 130 tests, HealthBridgeKit 77, UI suite 177 passed and 3 skipped (stack smoke, upgrade check and screenshots run from their own scripts), widget tests 15; package list, manifests, privacy scan and budgets (dashboard max 175 ms, chart render max 235 ms) pass. The performance test now swipes once to the source toggles, which the 44-point controls pushed below the fold: a scroll loop's queries flooded the log and evicted the first launch's signpost. Flaky (passed alone): `SpecialisedUITests` `testBodyCompositionEmptyRange`, `testEventsLinkedTypeAndEmptyRange` and `testLabAnalytePrintedUnitsRangeAndLabel` timed out synthesizing a tap during sign-in while the host was loaded.
