# J22.21 Local notifications

Epic: [E22 Vitamux iOS app](README.md) · Status: done · Depends on: J22.14, J22.19
Read: [ios-app#offline-cache-widgets-and-notifications](../../architecture/ios-app.md#offline-cache-widgets-and-notifications), [troubleshooting](../../operations/troubleshooting.md)

**Objective:** The owner hears about things that need them without the server pushing anything.

## Outputs
- A checker run from `BGAppRefreshTask` (alongside the HealthKit work) and on foreground: `GET /connections`, `/jobs?status=dead`, `/documents`, `/system/status`, plus the local Apple Health upload state.
- Categories: connection needs attention (needs_reauth, failing, degraded, stale); a job failed permanently; a lab document is ready for review; the backup is older than the panel's threshold; Apple Health upload stalled.
- Fires on a state change only, with the last seen state stored locally; one notification per item, updated rather than repeated.
- Text names the connection, document or job, never a health value. A tap deep-links to the screen that fixes it.
- Per-category toggles in app preferences; permission asked when the owner first turns one on, not at launch.

## Done when
- Unit tests for the transition logic (no repeat, update, clear when fixed).
- UI test: each category's deep link.
- The device campaign records how often iOS ran the refresh.

## Notes
- Code: `Features/Notifications/` (checker `Notifier`, copy and links `NotificationContent`, the permission row), transitions in VitamuxKit's `NotificationLedger` (unit tests `NotificationLedgerTests`), UI tests `NotificationsUITests`.
- Apple Health upload stalls when the device token is revoked, an enabled type failed its last run, or nothing uploaded for two days. A category turned off withdraws its notifications; turning it on notifies what is current. A source that cannot be read leaves its notifications as they were.
- The simulator's notification centre cannot be inspected: under `-uitest` the app lists what it would post in Settings › This app. Real delivery, the system tap and the refresh frequency (Settings › This app › Background checks) are device checks ([D19](../../apple-health-device-checklist.md)).
