# J20.5 Sign-in and MFA wizard for Garmin and WHOOP

Epic: [E20 Guided source setup in the web panel](README.md) · Status: todo · Depends on: J20.4, J18.2, J19.2
Read: [J17.2](../E17-sidecar-connectors/J17.2-remote-runtime.md), [connectors#typed-errors](../../architecture/connectors.md#typed-errors), [security#threat-model](../../architecture/security.md#threat-model)

**Objective:** Connecting an unofficial account feels like signing in to the provider's own app.

Builds on the generic auth steps of J17.2 (T17.2.4); this job is the finished experience for real providers.

## Outputs
- **One dialog.** It covers the whole flow:
  1. an unofficial-source notice with an explicit acknowledgement, which replaces "start disabled" for this connection;
  2. email and password;
  3. the MFA code, with method choice and resend where the provider has them (WHOOP: app or SMS);
  4. done, with the first sync queued.
- **Field hygiene.**
  - `autocomplete` hints for password managers: `username`, `current-password`, `one-time-code`.
  - The password and code are never put in URLs, browser storage or client logs, and are cleared from memory after submit.
  - The MFA session is held server-side for at most 10 minutes.
- **Errors in plain language:** wrong password; wrong code (retry without restarting); code expired; too many attempts or rate limited (with the wait time); account locked or captcha required (what to do in the provider's app); sidecar unavailable.
- **Reauth.** The same dialog, opened from the `needs_reauth` alert. Signing in to a different account is refused, as for OAuth.
- Provider-specific copy for Garmin and WHOOP: what syncs, the first backfill pace, and the risks, linking `docs/providers/<provider>.md`.

## Done when
- E2E with the Garmin and WHOOP sidecars in replay mode covers: connect with MFA, wrong code then right code, expired MFA session, rate limited, reauth of the same account, and a refused different account.
- The redaction audit, run through the UI flow, finds no password, code or MFA session in logs, the database, or browser storage.
