# J20.7 Devices: type, name and merge

Epic: [E20 Guided source setup in the web panel](README.md) · Status: done (2026-10-04) · Depends on: J20.6, J09.9
Read: [api#source-devices](../../architecture/api.md#source-devices), [frontend#navigation](../../architecture/frontend.md#navigation), [ADR-0016](../../adr/0016-canonical-writer.md)

**Objective:** The owner says what a device is and keeps one physical device's data on one device, so device-type rules (e.g. `builtin:steps`: watch › ring › band › phone) pick the right source. Providers do not always name or type a device: Garmin reports wellness data on the stand-in `garmin:wearable` and activities on the watch's own id.

## Outputs
- Migration `00030_device_management`: `devices.name`, `device_type_by_owner` (a type the owner set wins over the normalizer's), and `merged_into` (same owner and provider, never a chain).
- The canonical writer resolves a merged fingerprint to its target; dedupe keys keep the fingerprint, so reprocessing stays a no-op.
- `PATCH /source-devices/{id}` (type from the selector vocabulary `resolve.DeviceTypes`, name) and `POST /source-devices/{id}/merge` (one transaction: records of every canonical table move, dirty marks for the moved dates, audit); `GET /source-devices` adds fingerprint, name, `merged_into`, `device_types` and, with `include=records`, records per connection. Owner session only.
- Connections › Devices tab: type select, name field, "Merge into…" with a confirm dialog.
- Garmin VO2max rows sit on the wearable (`garmin.training` normalizer version 4).

## Done when
- Integration tests pin merge then reprocess: 0 new and 0 superseded rows, new records of the merged fingerprint on the target.
- Playwright covers type, name, merge and a refused change.
