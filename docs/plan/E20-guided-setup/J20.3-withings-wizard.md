# J20.3 Withings setup wizard

Epic: [E20 Guided source setup in the web panel](README.md) · Status: todo · Depends on: J20.2, J11.2
Read: [providers/withings#app-registration-and-callback](../../providers/withings.md#app-registration-and-callback), [frontend#navigation](../../architecture/frontend.md#navigation)

**Objective:** An owner who has never seen the Withings developer dashboard connects Withings without leaving the panel's instructions.

## Outputs
- Connections → **Connect a source** → Withings. When no app credentials exist, a three-step wizard opens:
  1. **Create the app.** A link to the Withings developer dashboard, and the exact values to enter, each with a copy button: the callback URL, plus a suggested app name and description. Readiness problems are shown first: no public URL, not https, IP host. The restricted-mode limit of 10 users is explained as harmless for one owner.
  2. **Paste the credentials.** Client id and client secret, using password-manager-friendly fields. Saving runs verify.
  3. **Connect your account.** The existing OAuth flow. An `invalid_client` or `redirect_uri` error returns to step 1 or 2 with the reason.
- Connections → Withings → Settings:
  - app credentials: "set", last changed, replace, remove;
  - "managed by the environment" when set by environment, read-only;
  - the notifications toggle, with the webhook explained.
- Copy for every failure in J20.1, in plain language and without provider jargon.

## Done when
- E2E against fake Withings, from a fresh install: wizard, verify, connect, first sync. Also: a wrong secret is reported at verify or at exchange; a mismatched callback points back to step 1.
- axe has no serious violations, and the route stays within the JS budget.
