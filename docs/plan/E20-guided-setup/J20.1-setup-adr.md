# J20.1 Setup model ADR and UX flows

Epic: [E20 Guided source setup in the web panel](README.md) · Status: todo · Depends on: None
Read: [connectors#source-setup-in-the-web-panel](../../architecture/connectors.md#source-setup-in-the-web-panel), [security#keys-and-secrets](../../architecture/security.md#keys-and-secrets), [ADR-0011](../../adr/0011-secrets-vault.md)

**Objective:** Decide how setup values are stored and which UI flow each provider gets, before any code.

## Outputs
- An ADR covering:
  - **Kinds of value.** Three kinds, each with one home:
    - provider app credentials (Withings client id and secret, and later other official OAuth apps): sealed rows in PostgreSQL;
    - account credentials (tokens): the existing `credentials` table;
    - sidecar shared secrets: generated files, or sealed rows for sidecars added in the panel.
  - **Precedence.** An environment or `*_FILE` value wins over the database and is shown read-only. Removing it falls back to the database value.
  - **Handling.** Secrets are write-only, with no reveal endpoint; the UI shows only "set" and the last change. Only an owner session can change them, and every change is audited.
  - **Sealing.** Purpose `credentials`, row-binding AAD `provider_app:<provider>`, covered by `vitamux keys rotate`.
  - **Liveness.** Changes apply without a restart.
  - **No Docker control.** The panel never controls Docker: no Docker socket, so it cannot start sidecars. It detects them and explains how to turn them on.
  - **No password storage.** Garmin and WHOOP passwords and MFA codes pass through once and are never stored.
- UX flows (wireframes in the ADR or `docs/architecture/frontend.md`) for:
  - "Connect a source" with a setup state per provider (`needs_app_credentials`, `needs_sidecar`, `ready`, `managed_by_environment`);
  - the Withings app wizard;
  - the sidecar-not-running card;
  - the sign-in and MFA dialog;
  - reauth, replacing a secret, and removing app credentials.
- [frontend#navigation](../../architecture/frontend.md#navigation) and [security#keys-and-secrets](../../architecture/security.md#keys-and-secrets) updated to match.
