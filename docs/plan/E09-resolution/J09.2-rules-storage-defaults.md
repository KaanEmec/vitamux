# J09.2 Built-in defaults, rule storage and versioning

Epic: [E09 Resolution engine](README.md) · Status: todo · Depends on: J09.1, J03.4
Read: [resolution-defaults](../../architecture/resolution-defaults.md), [resolution#selectors-and-validation](../../architecture/resolution.md#selectors-and-validation)

**Objective:** Safe defaults for every metric, plus immutable user rule versions.

## Outputs
- `builtin:<metric>:1` defaults in code, taken from the suggested ladders in [resolution-defaults.md](../../architecture/resolution-defaults.md) (mostly `first_available`, relay exclusion when the relayed provider is connected). Defaults may use the MVP [extensions](../../architecture/resolution.md#extensions) (E1, E2, E3, E5, E9); codes without a built-in in resolution-defaults.md (owner picks at onboarding) are exempt from "every metric has a default"; a default that needs a proposed one ships its plain form.
- `resting_heart_rate` and `hrv_rmssd_nightly` marked selection-only in `internal/catalog` ([metric-catalog#rules](../../architecture/metric-catalog.md#rules))
- Generated `docs/resolution-defaults.md`
- Migrations `resolution_rules`, `active_rules`; create version, activate, history, diff; audit

## Done when
- Every catalogue metric has a valid default. Each default matches resolution-defaults.md, or the difference is recorded there.
- Defaults are editable like any rule: the first edit copies the built-in, and nothing in the code treats a built-in as mandatory.
- An edit creates version+1; reactivating an old version works; audit shows actor and diff.
