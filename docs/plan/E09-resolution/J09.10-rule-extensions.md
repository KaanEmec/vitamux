# J09.10 Context ladders, window statistics, wear gate, coherence, hour composition

Epic: [E09 Resolution engine](README.md) · Status: todo · Depends on: J09.5, J09.6
Read: [resolution#extensions](../../architecture/resolution.md#extensions), [resolution-defaults](../../architecture/resolution-defaults.md)

**Objective:** The MVP rule extensions E1, E2, E3, E5 and E9, which the suggested defaults rely on.

## Outputs
- E1 `contexts`: workout and sleep windows come from aligned events (J09.6). Inside them, the listed groups go first.
- E2 `within_source.statistic: min_rolling_mean | min`, plus derived catalogue codes resolved from a source metric: `resting_heart_rate_nocturnal` (from `heart_rate`) and `spo2_night_min` (from `spo2`).
- E3 `quality.require_wear`: per-bucket wear check. Devices that never report the wear metric are exempt. Gated-out groups get `below_quality: not_worn`. Wear-based coverage for additive metrics.
- E9 `compose: {from: hour, op}`: additive `local_day` values built from hourly picks.
- E5 `follow`: use the leader metric's selected group for the same window, else fall back with warning `follow_unavailable`.
- Explanation templates and warnings for each extension.

## Done when
- Scenarios pass on fixturegen data:
  - a chest strap overrides the watch inside a workout only;
  - the ring leads HR inside the sleep episode only;
  - nocturnal RHR is the lowest 30-min mean of the main episode;
  - watch/phone/ring hourly steps with the watch taken off for some hours;
  - basal energy follows active energy's source, with a fallback day.
- Results are identical with and without the cache (J09.9 verify covers the derived code and followers).
