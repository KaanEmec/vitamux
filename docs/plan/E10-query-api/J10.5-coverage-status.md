# J10.5 Coverage and system status

Epic: [E10 Query and configuration API](README.md) · Status: done (2026-10-03) · Depends on: J10.1, J06.7
Read: [api#owner-endpoints-apiv1](../../architecture/api.md#owner-endpoints-apiv1), [reliability#health-logs-metrics](../../architecture/reliability.md#health-logs-metrics)

**Objective:** Diagnostics for sources and the instance.

## Outputs
- `/coverage` (source × day matrix from hourly aggregates)
- `/system/status` (versions, DB and blob sizes, last backup, degraded connections, failing jobs)

## Done when
- Coverage for the synthetic year returns in < 1 s; status reflects a seeded degraded connection.

## Tasks
- [x] T10.5.1 Write the coverage query. `internal/db/queries/status.sql` (`CoverageHours`) groups `source_hourly_aggregates` by metric, provider and local date in SQL; hours per day come from the owner's timeline (23 or 25 on DST days). A source is a provider; no `metric` filter returns every metric with data; at most 366 days per request.
- [x] T10.5.2 Implement status assembly. `internal/api/status.go`; last backup is `backup.Latest` on `VITAMUX_BACKUP_DIR` (manifest only, no MAC check or hashing); blob size is the stored size of the `blobs` rows (no directory walk); a degraded stream marks its connection (`stream` field); `failing_jobs` are dead jobs of the last 7 days, at most 50.
- [x] T10.5.3 Write the tests. `internal/api/status_integration_test.go` (seeded failing and drifting connections, dead jobs, backups; fixturegen slice for coverage) and `internal/backup/latest_test.go`.

## Measured

Full synthetic year (365 days, 16 metric/source rows, `VITAMUX_COVERAGE_YEAR=1 go test -tags integration -run TestCoverage ./internal/api/`): 92 ms for `GET /coverage`; the default 30-day slice takes 8 ms.
