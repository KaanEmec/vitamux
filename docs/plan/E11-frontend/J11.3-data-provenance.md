## Notes
- Routes: `(app)/data/` (daily view), `data/day/[metric]/[date]` (drilldown), `data/sleep`, `data/workouts`; components `ResultStatus`, `ExplainPopover`, `SeriesChart` (uPlot), `Modal`, `ProvenanceDialog`, `OverrideDialog`, `Hypnogram`; helpers in `src/lib/data/`. E2E: `e2e/data.spec.ts` on the stateful `e2e/data-fake.ts`.
- Render time: a 14,400-point day (plus a 1,440-point second source, two measurement pages) takes about 30 ms from data join to first paint (`vx-chart-render` User Timing mark, headless Chromium, Apple-silicon laptop, 2026-10-03); the e2e asserts < 500 ms. uPlot adds about 28 KiB gzip to the drilldown's lazy route chunk, not to the initial load.
- Provisional against the spec: `/metrics` (`Metric`), `/resolved/series`, `/resolved/sleep` and `/resolved/workouts` are open objects in `api/openapi.yaml`, so the UI does not call them. The metric picker reads `code` (and `windows`, if present) and falls back to a short list; the sleep view lists `/sleep?include=stages` sessions side by side; workouts are clustered in the browser (`lib/data/cluster.ts`, the resolver's overlap rule) from `/workouts`. Switch to the resolved events, with the selected member marked, once J10.3 types them.
- The drilldown chart reads each source's `records.href` from `/resolved/{metric}/{key}/sources` and pages `/measurements`; blood-pressure style family metrics need that link to chart.
