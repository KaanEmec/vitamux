# J13.2 Input hardening and fuzzing

Epic: [E13 Security and privacy hardening](README.md) · Status: done (2026-10-03) · Depends on: J05.4, J09.1, J12.1
Read: [security#threat-model](../../architecture/security.md#threat-model)

**Objective:** Robustness against hostile input.

## Outputs
- Fuzz targets (listed in the Makefile `FUZZ_TARGETS`; `make fuzz`): ingest batch and heartbeat, rule spec, PDF validator, lab extraction response, Withings measures normalizer and notification form, pagination cursor, OAuth state. HealthKit payloads and the Health app export are fuzzed since E15 (`FuzzNormalizeSamples`, `FuzzParseExport`).
- Limit tests for every upload path (`TestBodyLimits`, integration), plus a 64-level JSON nesting cap in `bodyLimits` and the ingest handlers

## Done when
- Nightly fuzzing has zero crashes; limit tests pass.

## Found by fuzzing
Cursor and OAuth state accepted non-canonical spellings (CR/LF skipped, spare bits ignored); Withings notification window check overflowed `time.Duration` (a 10^10 s window passed as small); a Withings record dated beyond year 9999 passed validation but cannot be marshalled or stored.
