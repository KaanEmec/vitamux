# J25.1 Mapping policy, field ledger and catalogue seed

Epic: [E25 Catalogue completeness and mapping corrections](README.md) · Status: todo · Depends on: None
Read: [metric-catalog#rules](../../architecture/metric-catalog.md#rules), [metrics.md](../../metrics.md)

**Objective:** Make "every provider value is catalogued" a tested rule, and add the codes the corrected mappings need.

## Outputs
- **Policy** in `docs/architecture/metric-catalog.md#rules`: a provider value gets a code (provider-scoped `<provider>_<name>` when proprietary); only identifiers, baselines, UI text and values derivable from stored rows stay raw, with a reason.
- **Field ledger** per stream: `internal/connectors/<p>/testdata/<stream>/fields.json` maps each raw JSON path to a code or to `raw: <reason>`. A shared test walks every golden raw fixture and fails on an unlisted key. Ledgers for every existing Withings, Garmin, WHOOP and Apple stream.
- **Catalogue seed** (new `Since` marker, `go run ./internal/catalog/gen`):
  - `total_energy` (kcal; interval and daily value; additive; built-in follows `active_energy`). Only reported totals are stored; active, basal and total are never summed or subtracted across codes.
  - Once-per-night codes, selection-only, split from their sample codes like `hrv_rmssd_nightly`: `spo2_nightly`, `respiratory_rate_nightly`, `skin_temperature_nightly`.
  - `intensity_light_time`, `intensity_moderate_time`, `intensity_vigorous_time`, `sedentary_time` (s; selection-only, definition in context), `elevation_gain`, `sleeping_heart_rate`, `sleep_awakenings`, `body_water_ratio`.
  - Provider-scoped codes for J25.4 and J25.5: `whoop_sleep_need`, `whoop_sleep_debt`, `whoop_sleep_consistency`, `whoop_sleep_disturbances`, `whoop_max_heart_rate`, `garmin_body_battery_charged`, `garmin_body_battery_drained`, `garmin_fitness_age`, `garmin_acute_load`, `garmin_chronic_load`.
- Sleep stages gain `unknown` (no data: neither asleep nor awake), `restless` and `out_of_bed` (`internal/normalize`).
- Device types gain `thermometer`, `under_mattress`, `glucose_meter`, `cgm` (`internal/resolve/rule.go`).
- Each new code gets a built-in or a `NoBuiltin` entry (the default rule, J24.1); its row moves out of `metric-catalog.md`.
- Known Open Wearables mis-mappings are recorded as "do not" notes: WHOOP kJ as active energy, a BMR rate as basal energy, total − active as basal, Oura equivalent distance as distance, lowest sleep heart rate as resting heart rate.
