# J25.4 WHOOP mappings

Epic: [E25 Catalogue completeness and mapping corrections](README.md) · Status: done (2026-10-05) · Depends on: J25.1
Read: [providers/whoop](../../providers/whoop.md), [ADR-0019](../../adr/0019-whoop-upstream.md)

**Objective:** WHOOP sleep stages are right and every WHOOP value is catalogued.

## Outputs
- **Sleep stages** on the live upper-case types: `LIGHT` light, `SWS` deep, `REM` rem, `WAKE` awake, `DISTURBANCES` awake, `LATENCY` in bed before sleep onset (feeds latency), anything else a gap with a warning. Session totals leave a stage nil when no event of it exists (the writer sets awake unconditionally today). The provider page lists the real type names.
- **Cycles:** `day_kilojoules` → `total_energy` (daily value at the main sleep's wake, ADR-0009; source unit kJ through the unit table); recovery `spo2` → `spo2_nightly`; `skin_temp_celsius` → `skin_temperature_nightly` (absolute °C); `calibrating` sets the `calibrating` quality flag on the rows derived from that recovery (rules can exclude it); sleep need and debt (`debt_pre`, the debt inside that night's need) → `whoop_sleep_need`, `whoop_sleep_debt`; consistency → `whoop_sleep_consistency`; disturbances → `whoop_sleep_disturbances`; `debt_post` → `whoop_sleep_debt_post` (the debt left after the sleep, not the debt inside the need); the need's parts → `whoop_sleep_need_habitual`, `whoop_sleep_need_from_strain`, `whoop_sleep_nap_credit`; `cycles_count` → `whoop_sleep_cycles`. What stays raw is derivable from stored rows (stage and latency durations, efficiency, wake counts, the day's average and maximum heart rate) or has no code yet (recovery components and baselines, sleep projections, the embedded workouts, intensity scores).
- **Heart rate:** `data = 0` is a gap, never a 0 bpm sample.
- **Workouts:** energy stays kJ in the source and is converted to kcal for the workout; strain → `whoop_workout_strain`, zone durations (ms) → `whoop_hr_zone_0_time` to `whoop_hr_zone_5_time`, altitude gain → `elevation_gain` and net change → `elevation_change`, all intervals over the workout keyed by its id; `percent_recorded` stays raw as quality metadata.
- **Body:** the sidecar stream `whoop.body` (developer API `/developer/v2/user/measurement/body`, one snapshot raw under a fixed key) and a normalizer: `max_heart_rate` → `whoop_max_heart_rate`, `height_meter` → `height` and `weight_kilogram` → `weight` as manual entries (the built-in rules do not select them), stamped with the fetch time.
- **Deep-dive steps** keyed by local date, so the timezone fix ([J24.6](../E24-resolution-visibility/J24.6-stream-reconcile.md)) supersedes rows instead of duplicating them.
- Version bumps and goldens for every changed stream.

## Done when
- Goldens include a night with every event type and a cycle with all fields; reprocessing gives sessions with deep and awake stages.
- The owner-side value-free checks from the research (stage sums equal the cycle's durations) are recorded in the provider page.
