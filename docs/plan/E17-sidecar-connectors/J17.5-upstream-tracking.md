# J17.5 Upstream tracking: automatic bumps, canary builds, sidecar image channel

Epic: [E17 Remote sidecar connectors and third-party collectors](README.md) · Status: in progress · Depends on: J17.3, J17.4, J13.6
Read: [connectors#third-party-collectors](../../architecture/connectors.md#third-party-collectors), [security#supply-chain](../../security.md#supply-chain)

**Objective:** A sidecar that wraps an upstream open-source library runs that library's latest release within a day, and an upstream release that breaks the sidecar never reaches a running install.

Owner decision (2026-10-04): wrapped upstreams (first [E18](../E18-garmin/README.md) `garminconnect`, [E19](../E19-whoop/README.md) `@dofek/whoop`) follow upstream releases automatically instead of waiting for a manual bump.

## Outputs
- **Linked source.** Each `sidecars/<name>/` depends on the upstream's registry release (PyPI, npm), which is built from its GitHub repository. The manifest names the package; the lockfile (`uv.lock`, `package-lock.json`) pins the exact version and hashes. `UPSTREAM.md` links the GitHub repo and the release tag that matches the locked version.
- **Automatic bumps.** A Dependabot entry per sidecar directory (`uv` or `npm`), checked daily, grouping the upstream package with any packages it releases in lockstep. A `cooldown` of 1 day (configurable per sidecar) lets a pulled or malicious release be caught before it is adopted.
- **Auto-merge on green.** A workflow approves and merges an upstream bump PR when every sidecar check passes: unit tests on synthetic cassettes, `vitamux connector-test` against the sidecar in replay mode, the Go normalizer goldens on the replayed raw, and the license gate. Any other dependency change in the same PR, or a failing check, leaves it open for review with the label `upstream-break` and the last good version stays live.
- **Upstream canary.** A nightly workflow builds each sidecar against the upstream's GitHub default branch (git dependency, not the registry) and runs the same checks. A failure opens or updates one issue per sidecar, so breakage is visible before the next upstream release lands.
- **Sidecar images.** A workflow, independent of core releases, builds `ghcr.io/<owner>/vitamux-sidecar-<name>` on every merge that changes `sidecars/<name>/`. Tags: `<upstream-version>-<short-sha>` (immutable) and `stable` (moving, latest green). Images are multi-arch, signed and carry an SBOM, like the core image.
- **Install channels.** The Compose profiles and the Coolify variant reference `:stable` by default, so `docker compose pull` (or a Coolify redeploy) picks up the newest upstream. The install docs show how to pin a digest instead and how to schedule the pull.
- **Visibility.** `GET /v1/describe` reports `upstream: {package, version, source_url}`. The core records it on the connection, shows it in the Connections UI, and audits a version change. Health links a `schema_drift` to the upstream version that introduced it.
- [connectors#third-party-collectors](../../architecture/connectors.md#third-party-collectors) and [security#supply-chain](../../security.md#supply-chain) updated: the lockfile pins, J17.5 bumps.

## Done when
Workflows, scope check and image pipeline are in place but inert until the first real sidecar lands ([E18](../E18-garmin/README.md)); the three checks below are verified then, on GitHub.

- A simulated upstream release on the example sidecar is merged and published as `stable` without human action.
- A simulated breaking release fails a named check, stays unmerged with `upstream-break`, and `stable` keeps the previous image.
- The canary opens an issue when the upstream default branch breaks the example sidecar, and closes it once fixed.
