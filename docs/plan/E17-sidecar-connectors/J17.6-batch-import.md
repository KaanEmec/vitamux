# J17.6 Replay a collector's archive (`vitamux import batches`)

Epic: [E17 Remote sidecar connectors and third-party collectors](README.md) · Status: in progress · Depends on: J05.3, J17.2
Read: [sidecars#replay-a-collectors-archive](../../sidecars.md#replay-a-collectors-archive), [connectors#push-ingest-contract](../../architecture/connectors.md#push-ingest-contract), [data-model#identifiers-and-dedupe-keys](../../architecture/data-model.md#identifiers-and-dedupe-keys)

**Objective:** History that an existing collector saved on disk joins the live connection for the same account, without duplicates and without a push token.

Dedupe keys use the connection's `account_key`, which only the connector's own sign-in sets. So a push connection can't receive another collector's archive for an account that later syncs live. The importer writes into the live connection instead.

## Outputs
- `vitamux import batches [--dry-run] DIR` (`internal/imports/batches.go`, `cmd/vitamux/import.go`).
  - Input: ingest batch v1 files (`*.json`, applied in name order) plus `blobs/<sha256>` for binary items.
  - Checks: the owner owns each connection and it is not disabled; blob content matches its name.
  - Writes: one `import` batch per file with its `migration_source`, then `StoreRaw` and synchronous normalization. A file with nothing new leaves no batch row.
  - `--dry-run`: validates and normalizes in memory, reports records, warnings and failures per stream, and exits 1 on any failure.
  - Records an `import_runs` row and an `import.batches` audit event.
- Shared importer setup: `withImportProcessor` (CLI), `soleOwner` and `normalize.Summary.Add`, used by the Apple Health export importer too.
- Guide section in [sidecars.md](../../sidecars.md#replay-a-collectors-archive); CLI table in [overview](../../architecture/overview.md).

## Done when
- The integration test with the synthetic Garmin goldens and a FIT blob covers these cases:
  - Dry run writes nothing.
  - The import normalizes every item.
  - A second run is a no-op with no empty batch.
  - An unknown connection, a blob hash mismatch or an invalid file is rejected before anything is stored.
