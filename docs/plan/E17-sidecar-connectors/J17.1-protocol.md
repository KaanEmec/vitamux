# J17.1 Protocol `vitamux-connector/1` contract

Epic: [E17 Remote sidecar connectors and third-party collectors](README.md) · Status: done · Depends on: J06.4
Read: [connectors#remote-sidecar-mode](../../architecture/connectors.md#remote-sidecar-mode), [connectors#connector-interface](../../architecture/connectors.md#connector-interface), [connectors#typed-errors](../../architecture/connectors.md#typed-errors)

**Objective:** A language-neutral, versioned contract that maps one-to-one onto the Go `Connector` and `Authenticator` interfaces.

## Outputs
- `api/connector-sidecar.v1.yaml` (OpenAPI 3.1) and JSON Schemas under `schemas/` for describe, auth steps, fetch request, NDJSON raw lines and the final `result` line, with synthetic examples
- An ADR that freezes v1 and states the versioning rules (additive only within v1, as for push ingest)
- Raw lines carry JSON bodies verbatim, or binary files (e.g. FIT, ZIP; ≤ 25 MiB as in push ingest) base64-encoded with `content_type` and `sha256` over the decoded bytes.
- `describe` reports the wrapped upstream (`package`, `version`, `source_url`) for [J17.5](J17.5-upstream-tracking.md).
- Auth steps cover OAuth2 redirect, MFA or code challenge, and device pairing. Credentials are opaque to the core, encrypted at rest, and sent to the sidecar only per call.

## Done when
- Each `Descriptor` field, auth step, `FetchResult` field and typed error class has exactly one protocol representation, and a Go test enforces this.
- The examples validate against the schemas.
