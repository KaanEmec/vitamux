# J17.2 Remote execution mode in the core

Epic: [E17 Remote sidecar connectors and third-party collectors](README.md) · Status: todo · Depends on: J17.1, J06.5, J11.2
Read: [connectors#remote-sidecar-mode](../../architecture/connectors.md#remote-sidecar-mode), [connectors#runtime-responsibilities](../../architecture/connectors.md#runtime-responsibilities), [security#threat-model](../../architecture/security.md#threat-model)

**Objective:** A sidecar behaves exactly like an in-process connector for scheduling, raw-first storage, health and UI.

## Outputs
- `internal/connectors/remote`: a `Connector` and `Authenticator` backed by the protocol client. NDJSON is streamed into `RawSink`, and problem+json maps to typed errors.
- Sidecar config: `VITAMUX_SIDECARS` (name, URL, secret file). Descriptors are fetched at start and on reconnect, and registered alongside in-process connectors. An unreachable sidecar makes its connections `degraded`; it never blocks startup.
- Timeouts, response size limits, private-network-only URLs, and a bearer secret per sidecar. Rotated credentials are persisted before use (single-flight).
- The UI auth wizard renders generic auth steps (redirect, code or MFA prompt). An `Official=false` sidecar shows the unofficial badge and starts disabled.

## Done when
- A fake sidecar completes the same lifecycle as fake Withings: connect, MFA, backfill, incremental, rotation, reauth, rate limit, schema drift.
- A malformed stream, timeout or oversized response fails only that job, with a typed error, and its raw data is never partially committed.
