# J26.2 30-second buckets and fine series grains

Epic: [E26 Intraday views on the server and the panel](README.md) · Status: todo · Depends on: J26.1
Read: [resolution#windows](../../architecture/resolution.md#windows), [api#owner-endpoints-apiv1](../../architecture/api.md#owner-endpoints-apiv1)

**Objective:** The engine and API serve one day at the catalogue's intraday resolutions.

## Outputs
- `30s` joins the bucket sizes everywhere they are listed (rule validation, the rule JSON schema, `/resolved/series`, OpenAPI, `resolution.md`); bucket windows stay uncached.
- `GET /resolved/series` points gain `min`, `max` and `n`; spans capped to 1 day for buckets of 1 min or less and 7 days for 5 min or more.
- `GET /sources/series` gains `grain=30s|1m|5m|15m|30m|raw` for spans of at most a day, read from `measurements` (the hourly aggregates stay for `hour` and `day`); `raw` pages by cursor; each source reports its native sample spacing.

## Done when
- OpenAPI has no drift; integration tests cover each grain, the caps and raw paging on synthetic data.
