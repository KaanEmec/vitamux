# J18.3 Streams, planning and backfill

Epic: [E18 Garmin Connect connector](README.md) · Status: in progress · Depends on: J18.2, J06.6
Read: [connectors#runtime-responsibilities](../../architecture/connectors.md#runtime-responsibilities), `docs/providers/garmin.md` (written in J18.1)

**Objective:** Fetch every Garmin data family incrementally and backfill history without tripping Garmin's limits.

## Outputs
- Streams (names final after J18.1), each with a default schedule, correction lookback, unit size and max backfill:
  - `garmin.daily_summary`
  - `garmin.heart_rate`
  - `garmin.steps`
  - `garmin.stress_body_battery`
  - `garmin.sleep` (stages, SpO2, respiration, HRV during sleep)
  - `garmin.hrv`
  - `garmin.respiration_spo2`
  - `garmin.activities`: summary and details as JSON, plus the original FIT file as a binary raw line
  - `garmin.body_composition`
  - `garmin.blood_pressure`
  - `garmin.training`: VO2max, training readiness and status
- Plan: day-sized units in the user's Garmin timezone. Incremental runs re-fetch the lookback days. Activities page by start time.
- Backfill paced slowly by default (rate limits plus a per-unit delay), resumable, cancellable.
- Raw lines carry each endpoint's response verbatim, with the endpoint and parameters in `request`.

## Done when
- A synthetic-year backfill, then incremental runs, has no gaps or duplicates; a re-fetched unchanged day is a no-op.
- A day Garmin revises inside the lookback creates a new raw version.
- An interrupted backfill resumes where it stopped.
