# J18.2 Garmin sidecar and sign-in

Epic: [E18 Garmin Connect connector](README.md) · Status: in progress · Depends on: J18.1, J17.2, J17.3
Read: [connectors#remote-sidecar-mode](../../architecture/connectors.md#remote-sidecar-mode), [connectors#typed-errors](../../architecture/connectors.md#typed-errors), [security#threat-model](../../architecture/security.md#threat-model)

**Objective:** A stateless Python sidecar that wraps `garminconnect`, signs a user in with MFA, and refreshes their session.

## Outputs
- `sidecars/garmin/` in the [J17.4 layout](../E17-sidecar-connectors/J17.4-third-party-packaging.md): Python ≥ 3.12, `pyproject.toml` plus `uv.lock`, Dockerfile on a digest-pinned base, non-root, read-only root filesystem, 256 MiB limit, healthcheck, `UPSTREAM.md` (repo, license MIT, unofficial).
- `describe`: provider `garmin`, `Official=false`, `AuthKind=InteractiveMFA`, streams from [J18.3](J18.3-streams.md), conservative rate limits from J18.1, and the upstream version.
- `auth/begin` (email and password) → an MFA step or success; `auth/continue` (code) → credentials; `auth/refresh`. Credentials are the library's token set as an opaque blob, sealed by the core. The password passes through once and is never stored or logged by the sidecar or the core.
- Error mapping: refused or expired session → `reauth_required`; 429 → `rate_limited` with Retry-After or a conservative default; network and 5xx → `transient`; an unexpected shape or a library parse failure → `schema_drift`; anything else → `permanent`.
- Sidecar tests on synthetic cassettes, plus a replay mode that serves J18.1 fixtures for the conformance kit and the core's lifecycle tests.

## Done when
- The sidecar passes `vitamux connector-test` for describe, auth (with and without MFA, wrong code, retry), refresh and every error class.
- The redaction audit, extended with a sentinel Garmin password, MFA code and token, finds no hits.
